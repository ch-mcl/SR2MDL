# 8. テクスチャ読み取り

importしたモデルにテクスチャを適用したい。

SR2ToolsにTXR(TEX)ファイルの解析コードが既にある。

- 解析本体: `src/io_scene_srally2mdl/SR2Tools/texture_classes.py`
  RTEX / RHBG / RTXR / MTEX の4種のシグネチャに対応。
  依存は`struct`と同梱の`bmp_handler`/`unyakuza`のみなので、Blender内でもそのまま動く。

- 呼び出し口: `src/io_scene_srally2mdl/SR2Tools/texture_tool.py` の `convertTXRtoBMPlist()`
  ただしPILを使用しており、Blender同梱のPythonにPILは無い(numpyはある)。
  BMP/PNGを経由せず、解析した画素バイトを`bpy.data.images`へ直接渡す形にする必要あり。

- 各モジュールが絶対import (`from bmp_handler import BMPv5` 等) のため、
  パッケージ内から使うには相対importへの変更が必要。

## 対応付けの解読結果

Node Transform の 0x0C (旧 `unk_0x0C`) が **Texture Index** だった。
5つのfloatの1つとして読んでいたため、NaN や 1.4e-45 (非正規化数) に見えていた。
32bit整数として読むと -1(テクスチャ無し) / 0 / 1 / 2。

- 提供された r_corolla の正解 (body, ホイール4, body, ホイール, 窓2) に対し
  `[0, 1, 1, 1, 1, 0, 1, 2, 2]` で完全一致。
- `-1` は色のみで描画されるメッシュ(ライト類, brake)。UVが1点に潰れている点とも一致。
- RIVIERA/finish.mdl は `[1, 0]` で、2枚のテクスチャを逆順に使う。
- DC版でも同じ値・同じ意味で成立。PC版固有ではない。

車はモデル同名のテクスチャファイルを持たず、下記を参照する。

- 0 = 車フォルダの `body.txr`
- 1 = 車フォルダの `ta_tire.txr` (路面別に de_tire / sn_tire もある)
- 2 = 車フォルダと同階層の `EFFECT/WINDOW.TXR` (全車共通)

DC版も同じ構成・同じ値で成立する(EFFECT フォルダも DCver 直下に置く)。
